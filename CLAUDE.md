## Git Workflow

### Branch Conventions

- **Feature branches**: `feature/<short-description>`
- **Bug fix branches**: `fix/<short-description>`
- **AI-assisted branches**: `claude/<task-description>` (auto-generated by Claude Code)
- **Never push directly to `main`** — always use a branch and PR.

### Commit Style

Write concise, imperative commit messages focused on the **why**, not the what:

```
add user authentication via JWT
fix violation status not persisting on page refresh
refactor report generation to use background jobs
```

- No ticket numbers or issue references in the message body unless required by team convention.
- Co-authored commits from Claude will include a `Co-Authored-By:` trailer — leave it in place.

### Push procedure

```bash
git push -u origin <branch-name>
```

Retry up to 4 times with exponential backoff (2s, 4s, 8s, 16s) on network failures.

## Code Conventions

### General

- Prefer editing existing files over creating new ones.
- Do not add error handling or validation for scenarios that cannot occur in practice.
- Default to writing no comments. Only add a comment when the **why** is non-obvious.
- Three similar lines of code is better than a premature abstraction.

### Naming

> Fill in language-specific conventions once the stack is set.

- **Files**: `kebab-case` (e.g., `violation-report.ts`)
- **Components** (if React/Vue): `PascalCase` (e.g., `ViolationReport.tsx`)
- **Functions / variables**: `camelCase`
- **Constants**: `SCREAMING_SNAKE_CASE`
- **Database tables/columns**: `snake_case`

### Security

- Never commit secrets, tokens, or credentials. Use `.env` (git-ignored) and `.env.example` for templates.
- Validate all input at system boundaries (user input, external APIs). Do not validate internal calls.
- Avoid common OWASP Top 10 vulnerabilities: SQL injection, XSS, CSRF, insecure direct object references, etc.

## AI Assistant Notes

When working in this repository, Claude (and other AI assistants) should:

1. **Read this file first** on every session to understand project conventions.
2. **Update CLAUDE.md** whenever new patterns, stack decisions, or conventions are established.
3. **Prefer targeted edits** — do not refactor unrelated code while fixing a bug.
4. **Do not introduce new dependencies** without confirming with the user first.
5. **Run tests** before marking any task complete. If no test suite exists yet, note that in the response.
6. **Never force-push** to `main` or any shared branch.
7. **Confirm before destructive operations**: deleting files, dropping tables, resetting data.
